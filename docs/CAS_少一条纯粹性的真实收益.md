## 0. 先对齐：你说「少一条」，我把账算全了

上一轮我把三条路压成了两条，你点出「少一条」。这里先把三条按**纯粹性代价**重新排开，并且钉死「少一条」到底少的是哪一条、以及**还有一处口径变化不能算进「一条」里**。

| | 路径 | 纯粹性代价 | 状态 | 是否对准已量化根因 |
|---|---|---|---|---|
| **1** | 训练（四阶段分布蒸馏 / instruct + LoRA SFT） | **保持** | O(1) | 补行为，不补 `q·k` 结构缺口 |
| **2** | **内容写入的 O(1) 叠加状态**（本轮实现） | **少一条**：核从「输入无关」变成「输入的函数」 | O(1)，无 N×N，无 KV cache | ✅ 直接对准 key→value 内容寻址 |
| **3** | Hybrid（保留少量 attention） | **放弃** | 引回 N×N + KV cache | ✅ 但有 KV cache |

**少掉的那一条**，精确表述是：SimplCore 原先最硬的「核完全输入无关」。CAS 的等效历史聚合核
$K_t(s) \propto \varphi(q_t)\cdot\varphi(k_s)$ 由当前 query 与历史 key 的**内容**决定，不再只是位置 $\tau$ 的函数。

**但必须一并说清的第二处变化**（否则「少一条」是低估）：双形式从
**FFT 并行 ↔ 二阶 IIR 递推**让位给 **prefix-cumsum 并行 ↔ 一阶累加递推**。
O(1) 状态本身不受影响，但论文 §4 定理 1 的分路径口径（fp64 数学等价、fp32 容差）
不适用于本模块——它是一条不同的数学族。`contract()` 里这两条都是显式 `False`，
不允许被包装成「纯 SGC 的小改进」。

**守住的四条**（机器可验证，见 8 项守护）：O(1) 常驻状态与 L 无关、
无 N×N 位置对打分、无 KV cache、严格因果（改未来不改过去）。
另外「流式 == 并行」仍成立：fp64 < 1e-10、fp32 容差内（偏差随 L 增长，与 SGC 的 FFT 路径同口径，不是逐位）。

## 1. 设计：一阶叠加状态

```
φ(·) = 1+elu(·) 或 特征维 softmax(·)·F      # 只对特征维，不涉及位置维 softmax
k_t, v_t, q_t = 三个分离的线性投影( u_t )    # R1 的卡点修复：key/value 不同源
S_t = S_{t-1} + φ(k_t) ⊗ v_t                # (F,V) 矩阵
z_t = z_{t-1} + φ(k_t)                      # (F,) 归一化
y_t = φ(q_t)ᵀS_t / (φ(q_t)ᵀz_t + ε)
```

`S` 与 `z` 的形状只由 `(F,V)` 决定，**与序列长度无关**。没有位置对矩阵，
没有历史 token 缓存。这是线性注意力族的内容写入状态，**不是 attention 模块**：
`purity.py` 的三层守卫按标识符扫描，本模块不含任何被禁标识符，也不在定义级豁免
白名单里——不靠改名、不靠豁免通过。测试 `test_source_scan_stays_clean_without_exemption`
锁住这一点。

## 2. 真实收益：MQAR 轴上第一次把静态核缺口补上

同任务、同 `1000 步 / 3 seeds / batch 8 / n_eval 256 / lr 3e-3`、同 chat 之外全部对齐。
**sgc 臂用 `init_mode="linear"` 的最强静态网格**，不拿塌缩的 logfreq 字典当靶子。

| 臂 | MQAR acc | accs（3 seeds） | 参数量 | 状态字节 | 核心乘加/层 |
|---|---:|---|---:|---:|---:|
| `sgc`（静态核，**最强网格**） | **0.2656** | 0.3086 / 0.2773 / 0.2109 | 15,370 | 8,960 B | $M\!\cdot\!D=512$ |
| `cas_elu`（φ=1+elu） | **0.3672** | 0.3555 / 0.3906 / 0.3555 | 18,120 | 8,448 B | $F\!\cdot\!V=1024$ |
| `cas_softmax`（φ=特征维 softmax） | **0.3711** | 0.3828 / 0.3672 / 0.3633 | 18,120 | 8,448 B | $F\!\cdot\!V=1024$ |
| `ts`（2 层因果 self-attention） | **0.3177** | 0.3125 / 0.2812 / 0.3594 | 34,760 | KV 随 L 增长 | 位置维 N×N |
| chance | 0.1250 | — | — | — | — |

配对 bootstrap（2000 次 percentile，同一 seed 逐对相减）：

| 对比 | 差 | CI95 | 判定 |
|---|---:|---|---|
| `cas_elu − sgc` | **+0.1016** | [+0.0469, +0.1446] | ✅ 显著 |
| `cas_softmax − sgc` | **+0.1055** | [+0.0742, +0.1524] | ✅ 显著 |
| `ts − sgc` | +0.0521 | [+0.0039, +0.1485] | ✅ 显著但 CI 很宽 |
| `cas_softmax − ts` | +0.0534 | [+0.0039, +0.0860] | ⚠️ **边缘显著**（下限几乎贴 0） |
| `cas_elu − ts` | +0.0495 | [−0.0039, +0.1094] | ❌ 不显著 |

**读法**：内容写入状态把静态核在 MQAR 上的缺口补掉约 **+0.10（38~40% 相对提升）**，
这是 v1~v5 加基、加门控、加适配、加步数都没做到的。在这个判据性任务与预算下，
`cas_softmax` 还以 **TS 一半的参数**（18,120 vs 34,760）达到并**边缘超过** TS 对照臂。

⚠️ **不许夸大的边界**：单任务、D=32 / 2 层 / 3 seeds / 1000 步 / 合成数据；
**TS 臂未调参**（统一 lr 3e-3 对 Transformer 未必最优）、**参数量不等**（逐臂记录，
不做等参断言）、`cas_softmax − ts` 的 CI 下限只有 0.0039。
所以这里的结论是「**机制方向成立、且成本可控**」，不是「CAS 优于 Transformer」。
`raw` 的 `honest_boundary` 字段写死了这条。

## 3. 成本账（你要的「平衡性能与成本」）

| 成本项 | 相对静态 SGC | 说明 |
|---|---|---|
| **常驻状态** | **−5.7%**（8,448 B < 8,960 B，同配置） | $F\!\cdot\!V+F = 1056$/层 vs $2MD+(K-1)D = 1120$/层。**状态不增反降** |
| **每 token 核心乘加** | **2×**（1024 vs 512 / 层） | 外积写入 + 矩阵读出。这是真实成本，不是零 |
| **参数量** | **+17.9%**（18,120 vs 15,370） | 多一个 `write_key` 投影（q/k/v 三路） |
| **推理时延** | 略增，与 L 无关 | O(F·V) 常数，不随上下文增长 |
| **长上下文** | 仍赢 | TS 的 KV cache 是 O(L·D)；CAS 状态恒定 |
| **纯粹性** | **少一条 + 换一族双形式** | 见 §0，这是最贵的成本，不是 FLOPs |

> 乘加口径说明：表中是**状态更新的核心项**，不含 `in_proj/out_proj/FFN` 的 $D^2$ 项
> （三臂都有、量级相同），不能拿它当全层 FLOPs 精确比较。

**1.7B 落地账**（D=2048 / 28 层）：
全尺寸 $F=V=2048$ → 状态 $4(2048^2+2048)\approx16.8$ MiB/层、28 层约 **470 MiB**，
对 2 GB 端机偏重；用低秩 $F=64$ 压到 $4(64\cdot2048+64)\approx524$ KiB/层、
28 层约 **14.3 MiB**，落在 680M 4 GB 显存预算内。
`test_low_rank_cuts_state_cost` 锁住这条降本路径，`contract()["flops_per_token"]`
逐层可查。CAS 的价值不在省算力，在**用 2× 常数算力换一个静态核根本做不到的能力轴**。

## 4. 与 v5 的关系：这正是它缺的那条轴

`docs/TS2SC_Q17_v5_direct_weight.md` 里，v5 的 A3 低通把 L27 残差 cos 从
0.2484 抬到 0.2622（+0.014），生成却仍是 `一 / 二 / 在`；精确核 oracle 证明
中层注入方向 cos ≈ 0，因为真实 attention 的方向由 $q_i\cdot k_j$ 内容匹配决定。
CAS 直接把这一项写进状态：§2 的 +0.1055 就是「补上内容寻址」在判据任务上的兑现。

**但别把它当成 1.7B 迁移已经成了。** 本轮没做的事，逐条列：

- 没把 CAS 接进 Qwen3-1.7B 的 28 层（那要重做逐层 profile、读出标定与注入幅度）；
- 没在 1.7B 上验证语言生成（「华为是什么公司」那一路仍是 v4 的词堆砌）；
- 没做长上下文 8K / 双形式漂移实测；
- 没做真实语料 ppl / KL 蒸馏（四阶段协议仍悬着，需真机算力）。

也就是说：**「少一条」这条路在机制层面被证实值得走，且代价第一次被量化；
从机制到可用模型之间，还隔着一次完整迁移。**
