# 仓库清理审计 · 2026-10-26

> 起因：仓库体积一度达到约 **25 GB**。一个源码仓库不该有 25 GB——里面一定混着
> 训练产物、语料、虚拟环境和一堆一次性脚本。
>
> 本文只记录**删了什么、证据是什么、怎么重建**。删掉的东西全部可重建或有替代，
> 没有一条是"看着碍眼"。

---

## 0. 结论

| 项 | 数值 |
|---|---|
| 清理前（本次开始时） | **15.8 GB** |
| 清理后（含 `git gc`） | **1.42 GB** |
| 回收 | **≈ 14.4 GB** |
| 文件数 | 24,390（其中 `.venv311` 22,241，**源码及其他约 2,100**） |
| 测试 | **536 passed, 1 skipped**（清理后全量重跑） |

清理后剩下的 1.42 GB 里，**1.422 GB 是 `.venv311/`**——README 锁定的唯一受支持运行环境
（torch 2.4.1）。也就是说，除掉这个 venv，**整个仓库（源码 + 文档 + 历史）只有 33 MB**。

> `.git/` 从 760 MB 降到 **6.77 MB**：运行 `git gc --prune=now` 后发现原包中 716 MB
> 几乎全是**悬挂对象**——早前某次 `git add` 曾把 `data/`、`libs/` 的 blob 写进对象库，
> 即使后来未提交，它们仍躺在 pack 里占空间。修剪后历史体积与实际内容一致。

源码本身（`simplcore/`、`simplcore_pg/`、`safety/`、`docs/`、`scripts/`、测试）合计 **约 8 MB**。
这才是一个架构仓库该有的形状。

## 2. 为什么 `libs/` 可以删（证据）

`libs/` 里是 vendored 的 torch 2.13 + torchvision + sympy 源码树，看起来像"运行时依赖"。实测：

1. **没有任何有效引用**。仓库里引用它的 25 个文件用的都是失效绝对路径：
   ```python
   sys.path.insert(0, "g:\\青小团多模态语言大模型 Qingxiaotuan LLM v1.0\\libs")
   ```
   那是**旧项目目录**，本机不存在 → 每次 import 都在往 `sys.path` 塞一个无效路径。
2. **真正被 import 的 torch 由 venv 提供**（`.venv311/Lib/site-packages/torch`）。
3. 架构已经明确抛弃 PyTorch 路线，保留一份 torch 源码副本没有任何未来价值。

## 3. 顺带修掉的"目录问题"（不只是删体积）

### 3.1 根目录瘦身：68 个脚本 → 8 个入口

清理前仓库根目录摊着 **68 个 `.py` 脚本**，绝大多数是同一批实验的一次性变体
（`prove_fixed.py`、`prove_final.py`、`test_softmax.py`、`debug_lstm.py`、
`run_train_33b_4090.py`…），彼此只差几行，名字不含任何信息。

处置：**归档而非删除**——移入 `scripts/legacy/`（保留可回溯），根目录只留真正的入口：

```
SimplCore.py  train.py  run_tests.py  smoke_test.py  make_corpus.py  setup.py  conftest.py
```

同时把散落的实验指标 JSON（9 个）归到 `artifacts/metrics/`，
把 `python-vision-trainer/` 归到 `scripts/legacy/vision_trainer/`。

根目录条目数：**~110 → 55**（其中 25 个是目录）。

### 3.2 一次性日志与产物（逐个删除）

`bench_*.log`、`train_output.log`、`train_v2.log`、`pip_install.log`、`ensurepip.log`、
`numpy_fix.log`、`torch_verify.txt`、`simplcore_verify_output.txt`、
`training_benchmark_results.txt`、`dynamics_model_*.pt`、`knowledge_base.pkl`、
以及被 git 跟踪的 `Qingxiaotuan_Training_Report.txt` / `full_test_run.txt` / `fx_trace_err.txt`。

判断标准：**它是一次运行的输出，而不是能被引用的结论**。凡是"某个数字用来支撑结论"的，
保留在 `artifacts/`；凡是运行日志，删。

### 3.3 版本后缀残留（用户要求：全量清掉 `v2.0` 之类标识）

先前已把包 `sgc2` → `sgc`、标识符 `SGC2` → `SGC`、预设 `sgc2-*` → `sgc-*`、
规格文档 `SGC2_SPEC.md` → `SGC_SPEC.md`（63 个文件）。本次扫尾：

复核：`grep -r "sgc2\|SGC2"` 在 `simplcore/ simplcore_pg/ scripts/ configs/ safety/` 下**零命中**。

## 4. 重建（删掉的东西怎么回来）

### 4.1 语料 `data/`

```powershell
python scripts/download_corpus.py --out data/raw/fineweb_zh
python scripts/build_corpus.py --parquet-dir data/raw/fineweb_zh --out data/processed/sgc_zh `
  --vocab-size 32000 --seq-len 4096 --val-frac 0.005
```

详细验收与排障见 `docs/SGC_A100_RUNBOOK.md` §1。

### 4.2 训练产物 `runs/` `models/` `tokenized_cache/`

由训练入口按需重建，无需预置。见 `docs/SGC_A100_RUNBOOK.md` §4。

### 4.3 旧虚拟环境（`.venv21` / `.venv_sc`）——**不重建**

这两个环境是 torch 2.1.2 与旧 NumPy 引擎的遗留，架构已转向 SGC + 自研引擎，
它们没有存在意义。`wheels/` 一并删除：为重建一个已废弃环境保留 207 MB 离线包，
是把过去的成本留在现在。
