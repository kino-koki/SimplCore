## 一、先把缺陷定位准：不是"聚合"，是"联想召回"

之前聚合任务两者打平（L=65 都到 1.000），说明问题不在感受野。改用 MQAR
（上下文放 G 个键值对，查询其中一个 key）——G>1 让"输出另一个稀有 token"
的聚合捷径失效：

| MQAR G=4，2 层，3000 步 | attention | SGC | chance |
|---|---|---|---|
| 准确率 | 0.500 | 0.3125 | 0.125 |

加上之前的精确指向（1.000 vs 0.398），两条独立证据同向：SGC 缺的不是
感受野，是 **key→value 绑定能力**。

## 二、根因：论文的轴 D 论证有个可反驳的漏洞

论文说"O(1) 状态 = 30.36 MiB 信息瓶颈 ⇒ 精确检索必输"。这一步把谱压缩的
有损性当成了常数状态的必然——但它不成立：**O(1) 只意味着"不随 L 增长"。
定容槽位存精确副本同样是 O(1)，且无损。**

所以轴 D 的正确表述是 **"SGC 当前的谱压缩状态在精确检索上必输"**，而非
"常数状态建模必输"。这是可修的工程缺陷，不是信息论天花板。

## 三、原型验证——失败，但定位到了真卡点

定容精确记忆（16 槽存精确副本、softmax 寻址，O(S·D) 与 L 无关）：
SGC 0.3125 → 加记忆 0.1875，且换三种写入策略（含 oracle）结果几乎相同
→ **卡点不在写入，在读取**。

诊断：槽内把 h_t 同时当寻址 key 和读出 value。查询是 h_k，值存在 h_v 槽
——两者无法匹配，因为配对关系是每样本随机、只存在于上下文内的。要召回
必须存**绑定 (key向量, value向量) 成对写入**，而逐 token 写入从原理上
造不出绑定。这正是 attention 用独立 Q/K/V + induction-head 做到的事
——架构层差异，不是容量问题。

**诚实声明**：原型有未解决的梯度异常（mem_Wq 梯度恒为 0，模块隔离测试
正常、接入后异常），所以"记忆无效"不能作为结论，该路线是**未验证**，
不是已证否。
（0.1-α 注记：R1 实现时在测试里复现了同款 in-place 版本冲突
（CopySlices）与"零初始化投影对自身二次损失梯度恒 0"的数学性质，
均已按"图外槽容器 + 下游损失供梯度"处理；另抓到并修复了
write_ptr/n_written 混用导致的 FIFO 回绕静默缺陷。）

**0.1-α 二期作废修正（2026-10-31）**：二期复现发现本文第三节"oracle
写入也无效、卡点在读取侧"的对照实验**因别名梯度 bug 完全无效**——
有限差分用 `p[k]=copy` 重绑定字典项而前向读旧数组，数值梯度恒 0；
原地扰动后 8 项参数 FD 全部 ratio=1.0000。**该实验结论作废**；
"槽内 h_t 同当 key/value 造不出绑定"的**机制分析独立成立**（R1 设计
依据）。R1 实测：MQAR 两 seed 均提升 SGC（+27%）、72% 参数在噪声内
**追平** attention，未超越——完整记录见
`docs/REPRODUCTION_REPORT_PHASE2.md`。

## 四、路线分级：一致性判据

**一致性判据**：状态是否与 L 无关？是否存在 O(L²) 两两交互？反 attention
的实质是反"状态随 L 增长 + O(L²) 交互"，不是反 softmax 算子本身。定容
检索是 softmax over S 个槽、O(S·D)、无 L 依赖——**不背叛架构**。

- **A 级（完全一致，优先）**：
  - **R1 定容绑定记忆**：写入单元从"单 token"改为"局部窗口绑定"
    （depthwise 局部卷积 K=4 天然覆盖 k、v 相邻），槽内 key/value 分开存。
    状态仍严格 O(1)。这是修复轴 D 的正路。✅ 已落地
  - **R2 修频率网格**（低成本先做）：实测 logfreq 网格 M=16 数值秩缺失
    （rank 14/16，条件数 1.6e16），与命题 5 的 |sinθ|→0 病态同源。
    ✅ 已落地（hybrid 网格，M=128 满秩 cond 1.4）
  - **R3 分层多尺度 decay_max**。✅ 已落地（`decay_scale`）
  - **R4 记忆升为一等公民**（§3.5 CMT 从"接线"提为核心 + 可微写入门）。⬜
- **B 级（可用但须标注）**：**R5 滑窗注意力混合**——窗口固定 ⇒ 状态仍
  O(1)，严格说不背叛，但削弱"纯 attention-free"叙事，应定位为务实
  fallback 并与 core 线分开宣称。⬜
- **C 级（背叛，不建议）**：全局注意力、随 L 增长的 KV cache、
  RoPE/YaRN——那就成了 TS，效率主张全部消失。❌

## 五、价值：正确的问题不是"质量上打赢"

追求"同算力下 ppl 更低"很可能打不赢，论文也不该这么宣称（§7 自述为
推测，§5.8 自承不显著）。SGC 真正、且 attention 结构性拿不到的价值在
**长上下文可行性**：1M 上下文 SGC 1.948 GiB vs TS KV cache 120 GiB——
这是数量级差异，不是百分比差异。

**正确宣称应是"在 X 长度以上唯一成本可行的选择"，而非"更好的模型"。**

结构性差异，不足以定量；R1 的验证未跑通，是分析结论不是实测结论
