# TS2SC-Q17 v5：直接改权重（self_attn → SGC + 系统适配）完整实录

日期：2026-11-05　基座：`Qwen3-1.7B-Instruct`（4.064 GB / 42 分片 / 311 张量）
脚本：`scripts/migration/q17_adapt.py`（v5）、`q17_adapt_lowpass.py`（ck6 消融）、
`q17_verify.py`（统一生成验证）；原始数据见 `artifacts/TS2SC_Q17_v5_*.json`。

> **本轮用户决策**：放弃四阶段分布蒸馏协议，改为「直接改权重：底层注意力
> 整体替换为 SGC，并做一系列适配」。本报告如实记录这条路的结果——
> **没有成功**，但把「哪一项适配有害、哪一项微幅有益」干净地分离出来了。

---

## 1. v5 与 v1~v4 的根本区别

v1~v4 做的是**把 attention 权重硬塞进 SGC 的壳**：`v_proj` 零填充进
`in_proj`、`o_proj` 折叠后零填充进 `out_proj`，SGC 实际只是 attention 的
静态近似器。v5 把每层 `self_attn` **当成整体模块移除**，插入一个完整的
`SpectralGlobalConv`，其每个张量都有明确来源与适配方式，逐条写进
`artifacts/TS2SC_Q17_v5_provenance.json`（28 层 × 9 类张量）。

| 张量 | 来源 |
|---|---|
| `in_proj` | teacher `v_proj`（行 0:1024）+ `k_proj`（行 1024:2048），v4 沿用 |
| `out_proj` | `fold_GQA(o_proj)` 列 0:1024（v2）+ **SVD(U) 列 1024:2048（A1）** |
| `coef` | 逐 KV 头 LS 拟合实测 attention profile → (32, 2048)（v4） |
| `rho / theta` | `init_mode="linear"` 正交网格 |
| `local_conv` | **profile 前 16 抽头 − sin 拟合核前 16 抽头（A3）** |
| `out_scale` | RMS 重标定（A4） |
| `norm` | teacher `input_layernorm.weight` 逐位复制 |
| `feed` | 零（不变） |
| `content_gate` | **OFF**（无解析初始化可用，开启会引入 4M 随机参数/层） |

Embedding / 28 层 FFN / 全部 norm / `lm_head` 逐位直搬不动。
**零梯度、零训练、零 pairwise、无 N×N、无 KV cache、零随机初始化参数。**

### 五项适配的动机

- **A1 full-rank 读出**：`D=2048` 但 `KV·HD=1024`，v1~v4 的 `out_proj`
  后 1024 列恒为 0，于是 `in_proj` 后 1024 行算出的卷积特征被全零乘掉，
  **一半容量白算**。用 `o_proj` 的左奇异向量 U 补齐这 1024 列。
- **A2 逐 KV 头 coef**：沿用 v4（修正 v1~v3 把 65536 自由度压成 32 的脚本简化）。
- **A3 低通适配**：`local_kernel` 4→16，用实测平均 profile 前 16 抽头减
  sin 基覆盖部分做残差抽头，补阻尼 sin 基族缺的平坦长尾。
  预检曾显示加 10 档 ρ^τ 衰减基可把 `ΣK/Σp` 从 0.178 拉回 1.000。
- **A4 RMS 幅度标定**：local 通道改变注入幅度后重标定 `out_scale`。
- **A5 provenance 账本**：逐张量可审计。

## 2. 逐层残差流诊断（五版对比）

同输入、同 chat template、37 token、`argmax` 无关的诊断前向。

| 版本 | L0 残差 cos | L0 注入 cos | L4 饱和范数 | L27 残差 cos | L27 注入 cos |
|---|---:|---:|---:|---:|---:|
| v1 解析直搬 | 0.8191 | 0.8459 | 94825 | +0.0518 | +0.4413 |
| v3 | 0.9041 | 0.9181 | 78233 | +0.2221 | +0.4749 |
| **v4（此前最佳）** | **0.9205** | **0.9263** | **66264** | **+0.2484** | +0.4553 |
| **v5 全适配（A1+A3+A4）** | **0.7951** | **0.7670** | 68994 | **−0.2445** | +0.2398 |
| **ck6 消融（仅 A3+A4）** | 0.9203 | 0.9262 | 66277 | **+0.2622** | +0.4646 |

**消融结论干净**：

- **退化 100% 来自 A1。** 移除 A1 后，L0 注入 cos 从 0.7670 回到
  0.9262（与 v4 的 0.9263 逐位一致到小数点后 3 位），L27 残差流 cos
  从 −0.2445 翻回 +0.2622。给冻结的 FFN 灌进 1024 维**未经训练的
  正交方向**，误差逐层放大，直接把末层残差流方向打翻。
- **A3 低通本身无害，且微幅有益**：L27 残差 cos +0.2484 → **+0.2622**、
  L27 注入 cos +0.4553 → +0.4646。
  ⚠️ 这个 0.2622 **超过上一轮报告的「静态核 oracle 上限 0.2476」并不矛盾**：
  那个 oracle 是在 `local_kernel=4` 的 v4 函数类内算的；ck6 加了 12 个
  低通抽头，函数类扩大了，上限自然抬高。它说明「补平坦长尾」方向对，
  但幅度只有 +0.014，远不足以改变生成。

## 3. 生成验证（原文，一字不改）

统一口径：Qwen3-Instruct chat template + no-think 预填、`NNEW=8`、
argmax 贪心、无采样无后处理。提示：**「华为是什么公司」**。
`artifacts/TS2SC_Q17_v5_verification.json` 是 raw。

```
teacher             : 华为技术有限公司（Huawei Technologies Co
ck4 (v4 最佳)       : \nOkay发现\n嗯发现宫\n
ck5 (v5 全适配)     : 前置\ufffd\ufffd\ufffdOULDOULDOULD
ck6 (仅低通)        : 一\n    二\n在\n
```

| 版本 | token 数 | distinct | rep3 | 中文占比 | 替换字符 |
|---|---:|---:|---:|---:|---|
| teacher | 8 | 8 | 0.0000 | 0.2581 | 无 |
| ck4 | 8 | 5 | 0.0000 | 0.4615 | 无 |
| **ck5** | 8 | **3** | **0.1667** | **0.1429** | **有（3 个）** |
| ck6 | 8 | 6 | 0.0000 | 0.3000 | 无 |

ck5 从「前置」退化成 3 个无效 UTF-8 字节，再退化成 `OULD` 单 token
循环（连出 3 次）——**这是 A1 引入的新故障，不是原模型固有**；ck6 无
重复但仍是碎片堆砌。

## 5. 结论：这条路走到边界了

1. **「直接改权重 + 零训练解析适配」在 1.7B 上没能让模型说正常汉语。**
   v5 全适配比 v4 **更差**（L27 cos 翻负、生成出无效字节和死循环）；
   ck6 消融微幅改善指标但生成仍不成句。
2. **A1 是明确的反面教材**：把 SVD 正交基填进冻结 FFN 的读出矩阵，
   等于给一个没有经过任何训练的 1024 维子空间开闸。provenance 账本
   保证「每个参数都有来源」，但**有来源 ≠ 有校准**。
3. **A3 证明方向对、幅度不够**：补平坦长尾能抬 L27 cos +0.014，
   但静态核与 attention 核的函数类不匹配没变。精确核 oracle 早已证明
   中层注入方向 cos ≈ 0（−0.03~0.06），真实 attention 的方向由
   `q_i·k_j` 内容匹配决定，平均 profile 与它近乎正交。
4. **指标与生成再次背离**，正好印证四阶段协议里「生成质量必须上主指标」
   那条：ck6 的 L27 cos 是本轮最高（0.2622），生成却是碎片；
   ck4 的中文占比最高（0.4615），内容仍是 `Okay发现`。
   **残差流余弦衡量「像不像 attention」，不衡量「会不会说话」。**
5. **与 WSP 的边界**：权重级手术能移除遮蔽（死循环），不能凭空添加
   能力。ck5 的死循环是 A1 引入的、可用解析手术移除的新遮蔽；而
   「不会回答、只会堆词」是能力/结构缺口，手术刀落不下去。

### 未做的，如实列

- **没有跑四阶段分布蒸馏**（用户明确改了方向）。若走那条，主指标应换成
  每位置 KL(teacher‖student)、val ppl、生成可读性，而不是残差流余弦；
  成功/证伪判据按协议预先写死，不事后圆。
- **没有解冻 FFN 做 SFT / LoRA**：2 核 / 2.4 GB 沙箱装不下 1.7B 全量训练。
- **没有加视觉编码器冲参数**：语言侧没跑通，堆参数无意义。
- **没有把 ck5/ck6 并入任何权重包**：当前最佳仍是 **ck4（v4）**，
  且它本身也不建议并入。

### 要越过边界只剩两条（都需要用户划界）

| | 纯粹性 | 说明 |
|---|---|---|
| **训练**：四阶段分布蒸馏 / instruct 基座 + LoRA SFT | 保持 | 唯一守住纯粹性的路；需真机算力，沙箱只够打通管线 |
| **架构**：内容写入的 O(1) 状态 `S_t=Σφ(k_s)v_sᵀ`，或 hybrid 保留少量 attention | 少一条 / 放弃 | 直接对准 key→value 内容寻址；架构级重写，不是迁移脚本 |

**静态核内部的调参空间已经被 v4 + 精确核 oracle 吃满**，再加适配、
再加步数、再每层 1000 步都绕不过函数类不匹配。这句话现在有五版
逐层数据、一次干净消融和四路同口径生成作证。
