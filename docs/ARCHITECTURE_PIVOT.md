## 0. 结论先行

**"抛弃 PyTorch"这件事，仓库里已经完成了七成，但完成在了错误的位置。**

| 路线 | 引擎 | 多模态 | 状态 |
|---|---|---|---|
| `simplcore/core/`（原 sgc2） | **PyTorch 2.4.1** | 无 | 493 项测试全绿，架构最强 |
| `simplcore/mix/` | **自研 `simplcore.tensor`（NumPy 自动微分）** | 代码在 `mix/multimodal/`，但 README 明确排除在主线外 | 可训，但架构弱于 SGC |
| `simplcore/tensor/` | 自研张量引擎：反向模式自动微分（拓扑排序 + 梯度累积）、AMP、梯度检查点、集合通信、显存预估、NumPy/CuPy/OpenCL 三后端 | — | **代码里显式拒绝 torch 后端** |
| `simplcore/engine/` | 统一 API + C++ 热路径 `csimplcore.cpp` + FFT + GPU | — | 第二层引擎，尚未与 tensor 层打通 |

**真实差距只有一条**：最强的架构（SGC）跑在 PyTorch 上；零依赖的那条路（mix）不是 SGC，且被刻意限定为纯文本。

所以正确的工程动作不是"重写"，而是 **把 SGC 移植到自研引擎，并把多模态从"排除项"改成"钉死的主线契约"**。

## 1. 必须直说的一条判断：零依赖 ≠ 零成本

`simplcore/tensor` 的自动微分是 **Python 层 tape**（`Tensor._backward` 可调用 + `_prev` 父指针 + 拓扑排序）。
这意味着**每一个算子调用都是一次 Python 函数调用 + 一次 NumPy/CuPy dispatch**。

量级估算（1.3B、seq 4096、micro-batch 4）：

* 单步算子调用数 ≈ 1.5e4 ~ 5e4（每层 SGC 块约 30~50 次）
* Python + dispatch 开销 ≈ 5~50 μs/次
* **纯 Python 开销 ≈ 0.4 ~ 2.5 s / step**，且 GPU 利用率会被压到个位数百分比

这正是 PyTorch 存在的意义：它的价值不在"能算"，而在**把算子调度下沉到 C++/CUDA 之后仍然能自动微分**。

**因此本蓝图的第一性约束是：**
> 自研化不是"用 Python 重写一遍 PyTorch"，而是"**把热路径编译掉之后重新实现自动微分**"。
> 只有 `simplcore/engine/csimplcore.cpp` 这条 C++/CUDA 路径能承载前沿规模。

这也决定了路线顺序：**先做 C++ 算子与融合核，再做 tape，而不是反过来。**

## 2. 目标架构：分层与算子清单

```
┌─ 训练栈 ──────── trainer / 调度 / 精度策略 / 断点续训 / 指标 ──────────┐
├─ 模块层 ──────── SimplCoreBlock / HybridBlock / FFN(SwiGLU) / 路由 / 多模态 ──┤
├─ 自动微分层 ──── simplcore.tensor 反向模式 tape（Python 层）──────────┤
├─ 算子层 ──────── ★ C++/CUDA 融合核（谱卷积 / 门控 / RMSNorm+SwiGLU）───┤
└─ 后端层 ──────── NumPy(CPU) / CuPy(CUDA) / OpenCL ────────────────────┘
```

### 2.1 必须自研的算子与反向策略

| 算子 | 用途 | 反向策略 | 难度 |
|---|---|---|---|
| `rfft` / `irfft` (实数 FFT) | 谱基卷积 | **重算法**：对 cotangent 再做一次正变换（`irfft(rfft(ĝ))`） | 中 |
| 阻尼振荡基核构造 `build_kernel` | 长程核 `K[τ,d]=Σ_m C[m,d]·ρ_m^τ·sin((τ+1)θ_m)` | 解析偏导：`∂K/∂ρ`、`∂K/∂θ`、`∂K/∂C` | 中 |
| depthwise causal conv1d | 短程路径 | 直接反传 + 环形缓冲 | 低 |
| 逐元素门控（sigmoid/逐位乘） | 选择性 | 解析偏导 | 低 |
| fused RMSNorm + SwiGLU | FFN | 手写融合核 | 中 |
| **融合谱卷积**（FFT 卷积 + 短程 + feed 三路合一） | SGC mixer 主体 | 一次内核完成三路累加 | **高** |
| GQA 滑窗注意力（仅 hybrid 路径） | 局部细节 | 环形 KV + RoPE 重套 | 高 |

**当前缺口**：`simplcore/tensor/tensor.py` **没有 FFT**。FFT 只存在于另一层 `simplcore/engine/fft.py`，
两套引擎尚未打通 —— 这是移植的第一块砖。

### 2.2 移植的验收标准（不可协商）

移植不是"跑起来"，是"**逐位对齐**"。每移植一个算子，必须通过：

1. **数值等价**：`max|Δ| ≤ 1e-5`（fp32），与 PyTorch 参考实现逐算子比对
2. **流式 == 整段**：逐位一致（现有 `test_streaming_matches_parallel` 守护）
3. **严格因果**：未来扰动不改变过去（现有 6 项因果性守护）
4. **梯度可达**：振荡器参数 `ρ/θ` 不得零梯度（现有 `test_oscillator_params_get_gradient_through_kernel` 守护）

**PyTorch 参考实现在移植完成前不得删除。** 它是唯一的黄金 oracle；
删掉它，移植就没有验收依据，只剩"看起来能跑"。

## 3. 多模态钉桩

### 3.1 钉桩原则

> 多模态是**编码器与路由**的问题，**不是核心算子**的问题。
> SGC 核心（阻尼振荡基谱卷积）在纯文本与多模态下必须是**同一份实现、同一组参数语义**。

这条原则的价值：多模态不会让核心算子分叉，就不会出现"文本分支已优化、图像分支未优化"的技术债。

### 3.2 三层结构

**第一层 · 统一符号化**
所有模态最终离散化为同构 token 序列，进入同一个 SGC 序列：

| 模态 | 编码 | 输出契约 |
|---|---|---|
| 文本 | 现有 `tokenization.py`（Char/Byte/BPE，可插拔） | `int32[B, L_text]` |
| 图像 | patch 切分 + 量化 → 离散 token | `int32[B, L_img]` |
| 音频 | 离散 codec token | `int32[B, L_aud]` |
| 视频 | 帧序列 + 时序段标记 | `int32[B, L_vid]` |

**第二层 · 模态编码器（可复用 SGC 块）**
视觉/音频编码器**复用 SGC 混合块**（谱卷积做全局结构 + 滑窗注意力做局部锐边），
不另起炉灶。这样文本与图像共享同一套算子与优化器实现。

**第三层 · 融合与路由**
* **早融合（默认）**：各模态 token 拼成一条序列。
  * 位置信息由**因果卷积/递推天然编码**（SGC 无位置嵌入表），跨模态拼接天然保持因果。
  * **模态路由门**：新增 `modality_router`，为每个 token 产生一个模态嵌入，
    在 mixer 输入处相加 —— 让谱基能区分"这段上下文来自图像还是文本"。
* **状态级融合（备选）**：各模态独立维护 SGC 流式状态（仍是 O(1)），
  通过一个跨模态门在状态空间融合。适合"长视频 + 长文本"、无法早拼的场景。

**钉桩的具体含义（落到代码契约）**：
1. `MultimodalConfig` —— **冻结**：字段一经确定不再随实验漂移
2. `ModalityEncoder` 协议 —— 统一 `encode(batch) -> int32[B, L]` 契约
3. **缺模态降级行为** —— 缺失模态必须能优雅退化为纯文本路径，且有守护测试
4. 模态路由门必须**不引入 softmax 注意力**（否则违背 attention-free 主张）

## 4. 四层闸门抗幻觉

### 4.1 设计动机

现有 SGC 只有 **L1 内容门控**（`u = W_in·h ⊙ σ(W_g·h)`）——它解决"按内容选择参与"，但不解决
"**当模型其实不知道时，不要编**"。幻觉的本质是：**在没有证据支撑的地方仍然生成了流畅的表示**。

四层闸门逐层收紧，每层对应一种不同的失败模式：

| 层 | 名称 | 拦截的失败模式 | 作用位置 |
|---|---|---|---|
| **L1** | 选择门 selective | 该参与的位置没参与 / 不该参与的乱参与 | mixer 输入（已有） |
| **L2** | 证据门 evidence | 依据不存在的远端上下文编造 | 谱基权重（核级） |
| **L3** | 不确定门 uncertainty | 高熵区域输出过度自信的确定值 | mixer 输出 |
| **L4** | 拒答门 abstention | 无依据时强行给出答案 | 输出头/解码 |

### 4.2 数学定义

**L2 证据门（核级）**

给每个谱基 m 一个由输入统计驱动的可信度：

```
e_m = σ( w_e · [ mean(u), var(u), ‖u‖₂ ] )        ∈ (0,1)^M
K_eff[τ, d] = Σ_m  e_m · C[m, d] · ψ_m[τ]
```

* `e_m` 逐位置计算 → 有效核**随内容变化**，与 L1 的位置级门控正交（L1 作用在输入 u 上，L2 作用在核上）
* **流式代价不增**：状态仍是 `2·M·D`；每步多一次 `(B,3)→(B,M)` 小投影
* **可解释性副产品**：`e_m` 的分布直接告诉我们模型"用了几分远端"

**L3 不确定门（输出级）**

用核能量与预测熵作为不确定性代理：

```
σ_t = entropy(p_t) / log|V|
u'_t = u_t ⊙ σ( −λ · σ_t / σ_0 )        # λ 可学，σ_0 为温度
```

高不确定性 → 收缩该位置的表示强度 → 让下游更依赖近邻证据而非长程外推。

**L4 拒答门（输出级）**

训练时用辅助损失做置信度校准，推理时低于阈值则输出拒答：

```
L_cal = BCE( logit_max , y )                  # 校准损失，权重 γ
推理： if max(p) < τ  →  输出 <abstain>
```

**总门**：`g_total = g_L1 ⊙ g_L2 ⊙ g_L3`，`g_L4` 在输出端独立作用。

### 4.3 约束（每一层都必须满足）

1. **可消融**：每层单独开关，`mixer` 预设增加对应变体
2. **流式 == 整段逐位一致**（L2/L3 会引入输入依赖，不能破坏对偶形式）
3. **严格因果**：`e_m`、`σ_t` 只依赖 `≤ t` 的输入
4. **梯度可达**：`w_e`、`λ`、温度必须收到梯度
5. **诚实边界**：四层闸门是**降低幻觉倾向的结构性约束**，不是"消除幻觉"的保证。
   必须用带引用/带证据的评测集实测（如 FaithEval / 自建引文校验集），
   **禁止在没有评测前宣称"抗幻觉"**。

### 4.4 与 `simplcore/architecture/gated_sgc.py` 的关系

旧 `gated_sgc.py` 是 **NumPy 引擎 + v2 核**上的门控实验（`gate` 作用于 SGC 输出与残差之差）。
它应当被**重新实现为上述四层闸门在 SGC 上的原生版本**，旧实现降级为消融基线。

## 5. HBM（显存）预算与优化

### 5.1 1.3B 规模预算（seq 4096，micro-batch 4，bf16）

| 项 | 计算 | 显存 |
|---|---|---|
| 参数 (bf16) | 1.33B × 2B | 2.66 GB |
| 梯度 (bf16) | 1.33B × 2B | 2.66 GB |
| master weights (fp32) | 1.33B × 4B | 5.32 GB |
| AdamW 状态 (fp32 m,v) | 1.33B × 8B | 10.64 GB |
| 激活（未优化） | 主导项 | 20~40 GB |
| 激活（优化后目标） | 见 5.2 | **≤ 8 GB** |
| **合计（目标）** | | **≈ 30 GB** → 单张 A100 80GB 可行，余量做 micro-batch 扩展 |

### 5.2 优化手段（按收益排序）

1. **8-bit 优化器状态**（Adam m/v 各 1B）→ 省 **8.6 GB**，几乎零精度损失
2. **选择性重计算**：只对 FFN / 核构造重计算；**FFT 卷积不重计算**
   （其反向本身就要重算一次正变换，双重重算会翻倍）
3. **核缓存**：`build_kernel` 只依赖 `ρ/θ/C`，流式路径每步重建是浪费 → 缓存 + 失效策略
4. **激活压缩**：SGC 的 `u`（B,L,D）是激活主项 → 存 bf16、算时升 fp32
5. **状态卸载**：优化器状态 offload 到 CPU 内存，HBM 不足时按需换入
6. **序列分块 + 梯度累积**：降低峰值激活
7. **融合算子**：减少中间张量落地（对显存和带宽同时有益）

### 5.3 前提：先测量再优化

仓库已有 `scripts/probe_batch.py`（实测分配器计数而非 RSS 猜测）。
**所有显存数字必须来自实测，不得靠算术估算填表。** 本文 5.1 的数字是"预算目标"，不是"实测结果"。

## 7. 风险登记

| # | 风险 | 影响 | 缓解 |
|---|---|---|---|
| R1 | **Python 层 tape 的算子开销** | 1.3B 训练不可用 | 热路径下沉 C++/CUDA；融合核；否则目标规模须下调 |
| R2 | 自研引擎缺 FFT 及其反向 | P1 阻塞 | P0 优先补齐；参考 PyTorch `torch.fft` 的反向结构 |

| R4 | 四层闸门"看起来有效" | 宣称失真 | 必须有带引用的独立评测集；无评测不宣称 |
| R5 | 多模态 tokenizer 的训练成本 | 预算超支 | 先用现成离散 codec；量化器从简 |
| R6 | 1.3B 以上从未实训过 | 全部下游结论无依据 | P4 之前不做任何规模外推宣称 |
| R7 | 零依赖与前沿规模的根本张力 | 战略级 | 接受"自研引擎 + C++ 内核"是唯一路径，或下调目标规模 |

| R9 | **闸门默认开启改变了模型行为** | L2/L3 默认 `True`，既有模型权重与新默认不等价 | 已记录于 `SGC_SPEC.md` §2.6；旧实验复现须显式 `evidence_gate=False, uncertainty_gate=False` |

## 8. 决策记录（2026-10-26 对话沉淀）

* **D1** 保留 PyTorch 路径作为**只读黄金 oracle**，直至 P5 验收条件全部满足。
  理由：移植的正确性只能靠对照验证，删掉参照物等于放弃验收。
* **D2** 去版本化只作用于**活架构身份**（`SGC2/sgc2/SGC 2.0/SGC 2.1`）；
  `.archive/` 完全不动，退役原型的历史命名（`sgc_v2`/`sgc_v3`/`SpectralGlobalConvV2`）保留，
  因为 `SGC_SPEC.md` 的科学对照表依赖它们。
* **D3** 多模态以**统一 token 化 + 复用 SGC 块 + 模态路由门**落地，
  核心算子不分叉；`MultimodalConfig` 冻结。
* **D4** 四层闸门 = 选择门 / 证据门 / 不确定门 / 拒答门，每层可消融、
  守护因果性与流式等价性；**无评测不宣称抗幻觉**。
* **D5** 显存数字一律实测归档，`probe_batch` 为唯一来源。
* **D6** 对话结论即时沉淀进 `.learnings/` 与本仓库文档，不停留在会话里。
* **D7** **Dreaming 是架构能力，不是 Agent 技巧**：反思发生在离线、产物是训练信号、
  作用对象是模型自身。CMT 的记忆机制作为 SGC 的一等能力实现
  （`simplcore/core/memory.py`），注入点用**残差流加性项**而非 KV
  —— 因为 SGC 无注意力、无 KV 缓存，引入 KV 等于把 Transformer 拽回来。
* **D8** 自进化的默认模式是 **`memory`（冻结基座）**，写回权重必须过
  no-regression gate。反思钩子是外部输入点，它的输出只是**候选信号**，
  最终由独立评测裁决。
