# 谱振流网络（SRFN）

> Spectral Resonance Flow Network
> 前身：SGC（Spectral Global Conv，谱全局卷积）
> 代码入口：`simplcore/core/ssm.py`、`simplcore/core/srf.py`
> mixer 名：`srf`（`sgc` 保留，旧实验可复现）

> ⚠️ **历史文档说明**：本文记录的是 SRFN 引入"推理注意力"（`ReasoningAttention`）
> 时的设计。该注意力模块已随整个注意力族一并从产品线**删除**
> （见 `.trash/attn_removed/`），SimplCore 现为**纯非注意力**架构。
> 因此下文 §2.3（推理注意力作为残差流第三段）与 §9（推理注意力 KV cache）
> 描述的机制**已不存在**；当前 SRFN 的残差流只有两段：`mixer → ffn`。
> 保留原文是为了说明 SRFN 的设计演化过程，**不是当前架构的描述**。

## 1. 为什么改名

旧名字"谱全局卷积"只描述了模型的一半：它确实用 FFT 做**固定核**的全局因果卷积，
卷积核由 M 个阻尼振荡基线性组合而成。

问题在于"固定"。同一个基在第 3 个 token 和第 300 个 token 上衰减速度完全一样，
模型没有能力说"这个位置的信息要记久一点，那个位置可以立刻忘掉"。

加入状态空间机制之后，衰减速度变成**由输入预测**的。这已经不是一个卷积该有的
性质了：核随位置变化，卷积的数学前提（时不变）不再成立。所以：

- **谱**：记忆基仍是阻尼振荡（不是纯衰减），能表达周期性结构；
- **振**：`rho`（包络衰减）与 `theta`（振荡频率）共同决定记忆的时间尺度；
- **流**：状态沿序列流动，流速（步长 Δ）由内容决定。

## 2. 加了什么，为什么

### 2.1 selective：让"记多久"可以被输入决定

原 `SpectralGlobalConv` 的递推是

```
y_t = a·y_{t-1} + b·y_{t-2} + c·u_t        a = 2ρcosθ, b = -ρ², c = sinθ
```

`ρ`、`θ`、`c`、`coef` 全是全局常数。新实现（`SelectiveSpectralSSM`）改成

```
λ_m       = ρ_m · exp(i·θ_m)
Δ_t       = softplus(W_Δ · h_t)[head]        ← 输入依赖，每 token 每头
h_t[m,d]  = λ_m^{Δ_t} · h_{t-1}[m,d] + b[m,d]·u_t[d]
y_t[d]    = Re( Σ_m coef[m,d] · h_t[m,d] ) + skip[d]·u_t[d]
```

三点设计取舍：

**为什么保留复特征（振荡）而不是用 Mamba 的实数衰减。**
实数 A 只能表达"遗忘"：信息单调衰减到 0。阻尼振荡能表达"以某个频率记住并周期
性回响"——语法结构、节拍、指代链这类**重复模式**需要它。代价是状态翻倍（实部+
虚部），但换来的是 S4D/Mamba 表达不了的一类记忆。

**为什么 Δ 是 per-token 标量而不是 per-head。**
第一版用了 per-head Δ（Mamba-2 的做法，`H=8`）。在 CPU 上它比 FFT 路径慢
**13 倍**（29 tok/s vs 400 tok/s）。剖析后发现问题不在矩阵乘，而在**中间张量的
尺寸**：`(B,H,M,C,C)` 的衰减张量与相位张量要各自过一次 `exp`/`cos`/`sin`，
每层每个 chunk 都来一遍，6 层 × 4 chunk × 2（实虚）= 48 次百万级三角函数。
去掉 head 轴后所有中间量小 8 倍，MAC 数不变，实测从 29 tok/s 回到 474 tok/s。

一个标量 Δ 仍然回答了真正重要的问题——"这个位置该比上一个位置记得更久吗"，
只是不能按通道组细分。这个取舍换来了 8 倍速度，而且可逆：GPU 上算力便宜时
可以加回 head 轴（代价是重新测一遍 chunk 大小）。

**为什么用 chunk 内 Toeplitz 而不是 associative scan。**
时变系统没有卷积核，FFT 直接用不了。可选路径有两条：associative scan（log T
深度，但 PyTorch 下需要多次物化中间量）和 chunk 内下三角矩阵乘。后者在
`C=32, M=16` 时只比纯 FFT 多 17% MACs，而实现的正确性容易验证——
`tests/test_srf.py::test_parallel_matches_streaming` 把它与逐 token 递推卡在 1e-5。

**为什么 `matmul` 而不是 `einsum`。** 5 维 `einsum` 走通用收缩路径，
`matmul` 对同样的操作数派发到批量 GEMM。同样的数学，CPU 上快约 2 倍。

### 2.2 推理注意力：嵌在因果链上，而不是另起一层

常规混合架构是**按层排布**：第 2 层 SSM、第 3 层 attention，轮流出现。信息必须
穿过中间层的 FFN 才能换路径，而且 attention 层不知道自己处在链的什么位置。

这里改成**平级挂在残差流上**，每层构成同样的三步循环：

```
x ← x + SSM(norm(x))        扫：把上下文压进 O(1) 状态
x ← x + g ⊙ Attn(norm(x))   聚焦：在具体位置上精确对齐
x ← x + FFN(norm(x))        改写：把两路结果写成下一步的表示
```

SSM 强在压缩（记不住"第 7 个 token 那个名字"，只能记"大概有个名字"），注意力强
在精确取用。平级放在同一层，等于每一步都能做一次检索-对齐，而不是等到某一层才做。

**门控 `g = sigmoid(gate)`，初值 -4（g≈0.018）。** 这不是调参技巧：小模型的自
注意力在随机初始化时输出接近噪声，直接全量加到残差流上会把 SSM 已经学到的信号
冲掉。门控让模型先学好 SSM 路径，需要精确对齐时自己把门打开。

**代价要写清楚**：注意力需要 KV。这里用**固定容量的环形缓冲**（容量 =
`attn_window`，默认 256），缓冲大小与生成长度无关——所以流式生成长文本时，
状态不会线性膨胀。代价是"零缓存"变成了"**定长**缓存"，且注意力只能看到
最近 256 个 token；窗口之外的信息靠 SSM 的状态记。

**为什么必须走环形缓冲而不是全量 KV。** "零 KV 缓存"是这个架构最早的卖点，
注意力一进来就得重新回答"要不要缓存"。答案不是"不要注意力"，而是
**"要一个不会随长度增长的缓存"**：环形缓冲的容量由窗口宽度决定，与生成长度
无关，`stream_bytes()` 因此仍然是常数（守护测试见 §4 第 10 条）。

**RoPE 是必须的。** 没有相对位置的注意力只能做"内容匹配"，分不清
"最近的"那个名字和"很早以前"的那个名字——而指代链和句法歧义恰好要靠
相对位置才能解开。实现上，key 在**写入环形缓冲之前**就按它自己的绝对位置
旋转好，所以环形覆盖掉旧 key 时不需要回头重算历史；查询按当前绝对位置旋转，
两者相乘自然得到正确的相对位置。

**流式与全量前向必须一致。** 环形缓冲保留的正好是前向窗口 mask 保留的那
`window` 个位置（`[i-window+1, i]`），两边的可见集合逐位相同，所以
`stream_step` 和 `forward` 在同一段输入上给出同一个答案。守护测试：
`test_reason_attn_keeps_streaming`（阈值 2e-3）。

## 2.3 一个容易漏掉的地方：推理注意力是残差流上的第三段

`SimplCoreBlock.forward` 的顺序是 **mixer → reason_attn → ffn**，三段各自带残差。
这不是风格选择：

```
x ← x + SSM(norm(x))        扫
x ← x + g ⊙ Attn(norm(x))   聚焦
x ← x + FFN(norm(x))        改写
```

把注意力放在 FFN 之后会让它读到的是"已经改写过的表示"，而不是"扫描后的
上下文"——那正是它需要去检索的对象。放在 FFN 之前，两条支路读的是同一个
`x`，它们是**平级**的。

同样的顺序在流式路径里也必须一致（`SimplCoreModel.stream_step`）：
`mx.step(x, st)` → `ra.step(x, ast)` → `blk.ffn(x)`。顺序错了的话，流式生成
出来的就不是训练时那个模型，而这种 bug 在 loss 曲线上完全看不出来。


## 3. 与旧 `sgc` 的关系：替代，不是叠加

谱核（FFT 全局卷积）和 SSM 的振荡基是**同一族数学对象**——前者是后者的
时不变卷积形式。两个都留着等于用两种算法算同一个量，白白多花一份算力。

所以：

| mixer | 记忆路径 | 并行算法 | 流式 | 用途 |
|---|---|---|---|---|
| `sgc` | 固定核，不可选择 | FFT O(L log L) | O(1) 状态 | 旧路径，历史实验 |
| `srf` | selective，Δ 输入依赖 | chunk 内 Toeplitz | O(1) 状态 | 新路径 |
| `srf` + reason_attn | + 精确检索 | + SDPA | O(1) 状态（定长环形 KV） | 需要对齐能力时 |
| `attn` | 纯注意力 | SDPA | 需全量 KV | 对照组 |

最后两行的差别只有"缓存会不会随长度增长"：纯注意力基线的 KV 随生成长度线性
增长，`srf` + 推理注意力用的是定长环形缓冲（容量 = 窗口宽度）。这正是
"注意力嵌进因果链"这件事能做到的**前提**——如果它必须缓存全部历史，那它
就不是一个能和 SSM 并列放在同一条残差流上的模块。

参数量对比（同宽深、`d=512 L=10`，`V=12288`）：

| 配置 | 参数量 | 相对 tuan-30m |
|---|---|---|
| `tuan-30m` | 30,085,298 | — |
| `srf-30m` | 30,290,178 | +0.7% |
| `srf-30m-attn` | 33,569,543 | +11.6% |

`srf` 比 `sgc` 多出的 20 万参数全部在 `dt_proj`（D→1）和 `b_in`/`coef` 上，
基本等参数。`srf-30m-attn` 多出的 11.6% 是每 2 层一个 q/o 投影，A/B 时必须用
它自己的对照。

### 3.1 速度代价（CPU，实测）

同配置 `d=320 L=6 T=128 batch=16`，单步训练（forward+backward+AdamW）：

| mixer | s/step | tok/s | 相对 |
|---|---|---|---|
| `sgc`（FFT） | 1.52 | 1345 | 1.0x |
| `srf` C=32 | 4.32 | 474 | 2.8x 慢 |
| `srf` C=64 | 3.60 | 569 | 2.4x 慢 |
| `srf` C=128 | 3.16 | 649 | 2.1x 慢 |

selective 的代价是实打实的。这是"每步都能决定记多久"的价格，不是实现没调好：
第一版是 29 tok/s（13x 慢），优化到 649 tok/s 靠的是三件事——去掉 head 轴
（中间量小 8 倍）、`matmul` 替换 5 维 `einsum`、缓存 `tril` 掩码。剩余的 2x
差距来自 Toeplitz 矩阵本身的 MACs，除非换算法否则消不掉。

**C 的选择**：`C=128` 在 `T=128` 时只有 1 个 chunk，没有跨块串行，所以最快。
但这依赖 `T ≤ C`；序列更长时要重新扫。

## 4. 验证覆盖了什么（`tests/test_srf.py`，23 项）

守护的是"看起来接上了、其实没接上"的几类错误：

1. **并行 = 串行**（1e-5）。这种 bug 不会在训练里暴露（loss 照降），只在线上
   生成时表现为答非所问，事后极难定位。
2. **块长无关性**（C=1,3,5,12,16 结果一致）。块长是实现细节，不能影响语义。
3. **不泄漏未来**。chunk 内是下三角矩阵，mask 方向写反会让模型偷看答案，
   训练 loss 会异常地好。
4. **Δ 真的依赖输入**。若 Δ 退化成常数，模型就是 S4，名字里的 selective 是假的。
5. **状态字节数与序列长度无关**。这是 O(1) 推理的定义，不是"大概差不多"。
6. **推理注意力的因果性**（含滑动窗口）。`attn_mask=None` 时 SDPA 默认**不是**
   因果的，必须显式 `is_causal=True`——这条踩过。
7. **门控可学**。初值接近关闭，反传后梯度非零。
8. **srf 与 sgc 参数比在 5% 以内**，否则 A/B 不公平。
9. **推理注意力不破坏流式能力**（阈值 2e-3）。注意力必须真正参与逐 token
   生成，而不是"训练时走全量前向、推理时走另一条路径"。
10. **环形缓冲容量与生成长度无关**。生成 200 个 token 后状态字节数与
    生成 6 个 token 时完全相同。
11. **存档 → 恢复 → 继续生成**，结果与不中断的生成逐位一致（1e-4）。
    漏掉"写了几个位置"这个计数，恢复后环形缓冲的写指针会错位。
12. **纯 attention 基线仍然报 `supports_streaming == False`**。它没有 O(1)
    状态，不能因为 SRFN 支持了流式就顺手把它也标成支持。

## 5. 实现踩过的坑（都留了测试）

这一节写的是**真实调试过程中出现过的错误**，不是假想的注意事项。每条都对应一个
测试，删测试就会复发。

**坑 1：mask 放在 `exp` 前面等于没放。**
`_chunk_kernel` 要把上三角（未来位置）置零。第一版写成
`diff = diff * mask` 然后 `amp = exp(diff * log_rho)`。上三角 `diff=0`，
`exp(0)=1` —— 掩码变成了"权重 1"，未来信息全进来了。
症状很迷惑：**chunk 最后一个位置完全正确，中间位置全错**（末位用不到上三角）。
修法是最后再乘一次 mask。测试：`test_no_future_leak`。

**坑 2：`squeeze(-1)` 在 `C=1` 时塌维。**
`delta` 形状 `(B,C,1)`，`squeeze(-1)` 得到 `(B,C)`；但 `C=1` 时 `(B,1)`
被压成 `(B,)`，后面 `cumsum(dim=1)` 直接越界。改用 `reshape(B, -1)`。
测试：`test_chunk_size_invariance[1]`。

**坑 3：`SDPA(attn_mask=None)` 默认不是因果的。**
`F.scaled_dot_product_attention` 不传 mask 时**完全不屏蔽**，每个位置能看整个
序列。以为"默认因果"是错的。必须显式 `is_causal=True`。
测试：`test_reason_attn_causal`。

**坑 4：五维张量 + `einsum` 让训练慢 13 倍。**
第一版用 per-head Δ，中间量 `(B,H,M,C,C)`，`cos`/`sin` 各过一次。实测 29 tok/s
（比 FFT 慢 13 倍）。剖析后确认瓶颈不是 MAC 而是中间量尺寸与算子调度。
去掉 head 轴 + `matmul` 替换 `einsum` + 缓存 `tril`，回到 649 tok/s。
测试：`test_srf_close_to_sgc_in_params` 之外，速度靠 `tmp/bench_train.py` 的记录。

**坑 5：状态布局 `(B,H,M,dh)` 与 `(B,M,D)` 之间用 `reshape` 会静默错位。**
`(B,H,M,dh)` 直接 `reshape(B,M,D)` 会把 H 和 M 两维的顺序搅乱——形状对、数值错，
而且不会报错。统一约定：**内部状态一律 `(B,M,D)`**，不做中间重组。

## 6. 实测

全部由 `scripts/train_30m_dialogue.py` 产出，用 `scripts/compare_curves.py` 汇总：

```
python scripts/compare_curves.py runs/ab_sgc_5m runs/ab_attn_5m runs/srf5m_fair
```

这个脚本会在配置不可比时直接喊出来。它存在的直接原因是我自己踩过一次：
`num_bases` 被 smoke 模式从 32 截成 16，参数量看起来仍然对得上，但记忆容量差了
一倍——**参数总量相等不等于配置可比**。跨 run 比数字之前先看这一行警告。

**实验设置**：同一份 `runs/talk2/synthetic_sft.jsonl`，`d=320 L=6 T=128 B=16`，
词表 494，`lr` 6e-4 → 6e-5 余弦，warmup 100，2000 步。三组的**唯一变量是 mixer**。

### 6.1 参数量对齐

| run | mixer | params | 相对 sgc |
|---|---|---|---|
| `ab_sgc_5m` | `sgc`（FFT 谱核，nb=32） | 5,763,294 | — |
| `ab_attn_5m` | `attn`（等参 Transformer） | 5,730,240 | −0.57% |
| `srf5m_fair` | `srf`（nb=32, `ffn_hidden=629`） | 5,763,300 | +0.0001% |

对齐到 ±6 个参数。这个精度不是洁癖：预算规划器靠 `analytic_params` 切宽深比，
参数差 1% 就会让"等参数对照"这句话不成立。

### 6.2 验证损失（同 step 对齐）

| step | sgc | attn | srf(nb=16) | srf−sgc |
|---|---|---|---|---|
| 100 | 1.9153 | 1.5193 | 1.8244 | −0.091 |
| 200 | 0.9873 | 0.5337 | 1.5502 | **+0.563** |
| 400 | 0.4259 | 0.2984 | 0.6721 | +0.246 |
| 600 | 0.2949 | 0.2483 | 0.3541 | +0.059 |
| 700 | 0.3075 | 0.2379 | 0.2938 | −0.014 |
| 900 | 0.2343 | 0.2104 | 0.2372 | +0.003 |
| 1000 | 0.2245 | 0.2086 | 0.2336 | +0.009 |

**读法**：`srf` 的收敛形状和 `sgc` 不一样——前 200 步落后 0.56，600 步收窄到
0.06，700 步反超，1000 步回到 +0.009（差 0.9%）。这不是噪声，是**冷启动慢**：

- selective 的 `Δ = softplus(W_Δ h)` 初值在 `dt_bias=-4`（≈0.018），意味着
  训练初期每个基的记忆窗口极短，模型几乎只在看当前 token。它必须先把 `W_Δ`
  学出来，才开始"用记忆"。固定核没有这个阶段。
- FFT 谱核在初始化时就有一个覆盖全序列的核，等价于"免费"拿到长程上下文。

所以这条曲线支持的说法只有一句：**在 2000 步以内、这个任务上，selective 追得上
固定核，但起步更慢**。它不支持"selective 更强"——`attn` 在同样步数上一直最好。

### 6.3 端到端训练吞吐

微基准见 §3.1，这里只补真实训练循环里的数字（含评测与存档开销）：

| run | mixer | tok/s | wall |
|---|---|---|---|
| `ab_sgc_5m` | `sgc` | 224 | 3328 s / 2000 步 |
| `ab_attn_5m` | `attn` | 194 | 2784 s / 2000 步 |
| `srf_5m` | `srf` C=128 | 151 | 2304 s / 1000 步 |

注意 `attn` 比 `sgc` 慢——注意力在 `T=128` 时也要走 SDPA，并不因为"没有谱核"
就更快。**慢 2x 是 Toeplitz 的固有代价**：FFT 把卷积变成 `L log L`，chunk 内矩阵
乘是 `O(L·C)` 的显式 MACs，C 越大越接近线性，所以 C=128 比 C=32 快。`C` 的
方向感很明确——往大调，直到显存放不下 `C×C` 的核。

### 6.4 还没测的

流式状态字节数随长度的变化（`scripts/bench_streaming.py`）**没跑出结果**。
§4 第 10 条那个"容量与长度无关"是测试断言（比较的是构造出来的状态张量大小），
不是长跑实测；本文件里也没有别处引用实测字节数。等机器 idle 时补。

## 7. 明确不声称

- **不声称 SRFN 比同参数 Transformer 更强**。当前只有 5~6M 规模的对话任务数据，
  任务本身在 2.5M 就饱和（话题对齐 7/8 = 7/8），**测不出架构差异**。要证明架构
  优势需要更长上下文、更大规模、更难的任务。
- **不声称 selective 一定优于固定核**。§6.2 只说明 1000 步追平，没有说明它更好；
  `attn` 在这个规模上仍然最优。selective 的自由度可能在小数据上只为过拟合服务。
- **不声称"零 KV 缓存"**。开 reason_attn 后缓存不消失，只是**不随长度增长**
  （定长环形缓冲，容量 = `attn_window`）。准确说法是"定长缓存"，不是"零缓存"。
- **不声称 chunked Toeplitz 在 GPU 上比 FFT 快**。CPU 上 FFT 在短序列反而慢
  （小算子开销），这个结论不能平移到 GPU；GPU 上要重新测。
